Why sparse autoencoders fail to respect feature geometry

A mathematical account of the representational limitations of rank-1 dictionary learning

1. The SAE setup

Given activations $\mathbf{a} \in \mathbb{R}^n$ from a neural network, a sparse autoencoder learns an encoder and decoder:

$$z_i = \text{ReLU}(\vec{w}_i^\top \mathbf{a} + b_i), \qquad \hat{\mathbf{a}} = \sum_{i=1}^{d} z_i \, \vec{d}_i$$

trained to minimise:

$$\mathcal{L} = \|\mathbf{a} - \hat{\mathbf{a}}\|^2 + \lambda \sum_{i=1}^{d} |z_i|$$

The first term demands accurate reconstruction. The second demands that as few coefficients $z_i$ are active as possible. Each dictionary element $\vec{d}_i$ is a fixed unit vector in $\mathbb{R}^n$, and each $z_i \geq 0$ is its scalar coefficient.

2. The assumption baked in

The reconstruction $\hat{\mathbf{a}} = \sum_i z_i \vec{d}_i$ says: the activation is a sparse sum of scaled directions. The contribution of dictionary element $i$ is always:

$$z_i \, \vec{d}_i \;\in\; \text{span}(\vec{d}_i)$$

This is a point on a one-dimensional ray through the origin (a ray because $z_i \geq 0$). No matter what $z_i$ is, the contribution can only slide along $\vec{d}_i$. Each atom is rank-1 by construction.

This embodies the linear representation hypothesis: every feature is a direction, every activation is a sparse superposition of those directions. When true — for example, if the model represents "is French" as one direction and "is code" as another — the SAE recovers those directions cleanly.

3. Features with geometry

Some features are not directions. They have internal structure — a set of related values that live on a manifold within a multi-dimensional subspace.

Consider "day of the week." A model represents the seven days as points on a circle in a 2D plane spanned by two orthogonal directions $\vec{e}_1, \vec{e}_2 \in \mathbb{R}^n$:

$$\mathbf{a}_{\text{day}}(\theta) = \cos(\theta)\,\vec{e}_1 + \sin(\theta)\,\vec{e}_2, \qquad \theta = \frac{2\pi \cdot d}{7}, \quad d = 0, \ldots, 6$$

This is one feature (which day it is) but it has a 2-dimensional geometric structure (a circle). The two components are coupled by the constraint $\cos^2\theta + \sin^2\theta = 1$. No single direction $\vec{d}_i$ can capture this — a ray cannot approximate a circle.

4. Three failures

Failure 1 — The ReLU forces non-negative coefficients

Even if the SAE learns $\vec{d}_1 = \vec{e}_1$ and $\vec{d}_2 = \vec{e}_2$, the reconstruction can only reach the first quadrant:

$$\hat{\mathbf{a}} = z_1 \vec{e}_1 + z_2 \vec{e}_2, \qquad z_1 \geq 0, \; z_2 \geq 0$$

But the circle passes through all four quadrants. Monday might sit at $(\cos\theta, \sin\theta) = (-0.22, -0.97)$. To reach negative coordinates, the SAE needs additional elements $\vec{d}_3 = -\vec{e}_1$ and $\vec{d}_4 = -\vec{e}_2$. One 2D feature has already been split into four dictionary elements, and representing any point on the circle requires two of these four active simultaneously.

Failure 2 — The sparsity penalty punishes co-activation

Suppose the activation is at angle $\theta = \pi/4$:

$$\mathbf{a} = \tfrac{\sqrt{2}}{2}\,\vec{e}_1 + \tfrac{\sqrt{2}}{2}\,\vec{e}_2$$

Option A: two basis elements

$z_1 = z_2 = \frac{\sqrt{2}}{2}$

Sparsity cost: $\lambda(z_1 + z_2) = \lambda\sqrt{2}$

Option B: one dedicated element

Learn $\vec{d}_5 = \frac{\sqrt{2}}{2}\vec{e}_1 + \frac{\sqrt{2}}{2}\vec{e}_2$, then $z_5 = 1$

Sparsity cost: $\lambda \cdot 1 = \lambda$

Option B always wins. More precisely, for any unit-norm point $\mathbf{a}$, using a single aligned dictionary element costs $\lambda$. Using any two non-aligned elements at angle $\alpha$ apart costs at least:

$$\lambda(z_1 + z_2) \;\geq\; \frac{\lambda}{\cos(\alpha/2)} \;>\; \lambda$$

The $L_1$ penalty is minimised along dictionary directions and penalises any interpolation between them. So the SAE is driven to learn a separate dictionary element for every angle it frequently encounters — tiling the circle with discrete directions.

Failure 3 — The geometry is destroyed

The SAE tiles the circle with $d'$ dictionary elements at evenly spaced angles:

$$\vec{d}_j \approx \cos(\theta_j)\,\vec{e}_1 + \sin(\theta_j)\,\vec{e}_2, \qquad j = 1, \ldots, d'$$

This destroys the geometry in three ways:

(a) Topological structure is lost. On the circle, Sunday is adjacent to Monday — the circle wraps around. In the SAE's representation, "Sunday-direction" and "Monday-direction" are unrelated dictionary elements. The adjacency is not encoded.

(b) Metric structure is lost. On the circle, Thursday is closer to Friday than to Monday. In SAE space, each day fires a different element with $z_j \approx 1$ and all others near zero. The representations of Thursday and Friday are as different as Thursday and Monday — both are approximately one-hot in different coordinates.

(c) The feature count is wrong. There is one feature ("day of the week") but the SAE reports $d'$ features. Each day appears as a separate learned direction. Downstream analysis that counts features, measures polysemanticity, or studies feature interactions is systematically wrong — it is counting fragments of one geometric object as independent features.

5. The root cause

The SAE's representation space is:

$$\mathcal{R} = \left\{\sum_{i=1}^{d} z_i \vec{d}_i \;\Big|\; z_i \geq 0\right\}$$

This is a convex polyhedral cone — a union of flat faces. Its geometry is always piecewise linear: each face is a simplex spanned by a subset of dictionary elements, and moving continuously through $\mathcal{R}$ means linearly interpolating between faces.

Any curved manifold — a circle, a sphere, a rotation group, a torus — cannot be faithfully embedded in a polyhedral cone. The SAE can only approximate curved geometry by adding more flat faces, which means more dictionary elements, which means more splitting.

The worst-case approximation error for a unit circle with $d'$ evenly spaced dictionary elements is:

$$\max_\theta \min_j \|\mathbf{a}(\theta) - \vec{d}_j\| = 2\sin\!\left(\frac{\pi}{d'}\right) \approx \frac{2\pi}{d'}$$

Reducing error requires more elements, which inflates the feature count without bound. This is not a training failure or a hyperparameter issue. It is a representational limitation of the architecture.

The sparse autoencoder assumes all features are rank-1. When they are not, it shatters them into fragments, loses their geometry, and conflates representational capacity with feature count. No amount of scaling, tuning, or training resolves this — it is structural.
